```bash

```

## Uso

```tsx
import { Calendar } from "@blips/ui/components/calendar"
import { ptBR } from "react-day-picker/locale"
```

```tsx
const [date, setDate] = React.useState<Date | undefined>(new Date())

return (
  <Calendar
    mode="single"
    selected={date}
    onSelect={setDate}
    locale={ptBR}
    className="rounded-lg border"
  />
)
```

## Sobre

O componente `Calendar` é construído sobre o [React DayPicker](https://react-day-picker.js.org) v9. Os botões de navegação e de dia usam o `Button` da lib.

Passe `locale={ptBR}` (de `react-day-picker/locale`) para nomes de mês e dia da semana em português. O `Calendar` repassa o `locale` para o `CalendarDayButton` e para o dropdown de mês.

## Calendário persa / hijri / jalali

Para usar o calendário persa, troque o import do `DayPicker` por `react-day-picker/persian` numa cópia local do componente.

```diff
- import { DayPicker } from "react-day-picker"
+ import { DayPicker } from "react-day-picker/persian"
```

## Data selecionada (com fuso horário)

O componente aceita uma prop `timeZone` para garantir que as datas sejam exibidas e selecionadas no fuso horário local do usuário.

```tsx
export function CalendarWithTimezone() {
  const [date, setDate] = React.useState<Date | undefined>(undefined)
  const [timeZone, setTimeZone] = React.useState<string | undefined>(undefined)

  React.useEffect(() => {
    setTimeZone(Intl.DateTimeFormat().resolvedOptions().timeZone)
  }, [])

  return (
    <Calendar
      mode="single"
      selected={date}
      onSelect={setDate}
      timeZone={timeZone}
    />
  )
}
```

**Nota:** se a data selecionada aparecer deslocada (por exemplo, selecionar o dia 20 destaca o dia 19), confira se a prop `timeZone` está com o fuso horário local do usuário.

**Por que no cliente?** O fuso horário é detectado com `Intl.DateTimeFormat().resolvedOptions().timeZone` dentro de um `useEffect` para manter a compatibilidade com renderização no servidor. Detectar o fuso durante a renderização causaria divergência de hidratação, já que servidor e cliente podem estar em fusos diferentes.

## Migrando da v2

A API do `Calendar` continua a do React DayPicker. O que muda:

- `CalendarDayButton` aceita a prop opcional `locale`. O `data-day` e o dropdown de mês passam a formatar com `locale?.code` em vez de `"default"`.
- A chave `table` de `classNames` (deprecada no DayPicker v9) deu lugar a `month_grid`. Quem sobrescrevia `classNames.table` deve usar `classNames.month_grid`.
- Visual: `--cell-size` caiu de `spacing(8)` para `spacing(6)` e entrou `--cell-radius` (`radius-md`). Hoje, o intervalo selecionado e o meio do intervalo usam `bg-muted` em vez de `bg-accent`. Com `captionLayout="dropdown"`, os selects de mês e ano ficam sem borda e sem fundo.
- Os ícones de navegação agora são `CaretLeftIcon`, `CaretRightIcon` e `CaretDownIcon`.

```tsx
// v2
<Calendar classNames={{ table: "w-full" }} />

// v3: para manter o tamanho de célula antigo e trocar a chave da grade
<Calendar
  className="[--cell-size:--spacing(8)]"
  classNames={{ month_grid: "w-full" }}
/>
```
