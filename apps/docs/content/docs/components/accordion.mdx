## Instalação

```bash
npm install @blips/ui
```

## Uso

```tsx
import {
  Accordion,
  AccordionContent,
  AccordionItem,
  AccordionTrigger,
} from "@blips/ui/components/accordion"
```

```tsx
<Accordion defaultValue={["item-1"]}>
  <AccordionItem value="item-1">
    <AccordionTrigger>É acessível?</AccordionTrigger>
    <AccordionContent>
      Sim. Segue o padrão de design WAI-ARIA.
    </AccordionContent>
  </AccordionItem>
</Accordion>
```

Por padrão só um item fica aberto por vez, e clicar de novo no item aberto o fecha. `value` e `defaultValue` são sempre arrays, mesmo nesse modo.

## Migrando da v2

- As props `type="single" | "multiple"` e `collapsible` saíram. Use `multiple` para abrir vários itens; todo item já fecha ao clicar de novo.
- `value` e `defaultValue` agora são **sempre arrays**. `onValueChange` recebe `(value: any[], eventDetails)`.
- `AccordionContent` é um `Accordion.Panel`: `forceMount` virou `keepMounted`, e entrou `hiddenUntilFound`.
- Atributos de estado: `data-state="open" | "closed"` virou `data-open` / `data-closed` no item e no painel. O trigger ganha `data-panel-open` e `aria-expanded`, e o disabled vira `aria-disabled`.
- `asChild` no trigger virou `render`.
- Visual: a raiz virou uma caixa com borda (`rounded-md border`), o item aberto ganha `bg-muted/50` e o texto passou para `text-xs/relaxed`.

```tsx
// v2
<Accordion type="single" collapsible defaultValue="item-1">
  ...
</Accordion>
<Accordion type="multiple" defaultValue={["a", "b"]}>
  ...
</Accordion>

// v3
<Accordion defaultValue={["item-1"]}>
  ...
</Accordion>
<Accordion multiple defaultValue={["a", "b"]}>
  ...
</Accordion>
```
